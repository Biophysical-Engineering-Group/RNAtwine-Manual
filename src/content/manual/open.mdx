## Designs, the library and folders

RNAtwine reads a design as pyFuRNAce exports it: an oxDNA configuration (`.dat`) and, beside it, the dot-bracket structure with its pseudoknot table (`.txt`).
The topology (`.top`), the base-pair traps (`_forces.txt`) and the pyFuRNAce blueprint (`.json`) are read when they are there, but a design does not need them.
Because the files of one design share a name, any one of them opens the design, and RNAtwine finds the others beside it.

The buttons at the top of the page choose where the designs come from:

- **Library** opens the published designs that come with RNAtwine, from the `library/designs/` folder of the repository the app was built from.
  These designs come with their saved setups for dimers, rings and clasp isomers.
- **Folder...** opens a folder of your own designs, together with the folders one level down.
  **Rescan** reads the folder again after its files have changed on disk.
- **Open...** opens a single file of any kind that RNAtwine reads ([below](#opening-any-file-with-open)).

<Figure name="open-library" />

The designs of the open folder are listed as cards, each giving the design's size in nucleotides, its kissing loops and its saved setups.
A card also notes when the design's sequence holds `N` or `K` placeholders.
Type part of a name in the field above the cards to filter them, and click a card to open its design.
A design that cannot be built shows the reason on its card and does not open.
A group of files that lacks a required file is listed as incomplete.
When the environment variable `RNATWINE_DESIGNS` names a registry of designs, the page also offers a picker of the registry's designs by name.

## Opening any file with Open...

Because a `.dat` can hold either a pyFuRNAce design or an oxRNA configuration, RNAtwine recognizes a file from its extension and, for a `.dat` or a `.top`, from the files of the same name beside it, as the table shows.

| file | opens as |
|---|---|
| a design's `.dat`, `.txt`, `_forces.txt` or `.top`, when the design's `.dat` and `.txt` are both there | the design |
| a pyFuRNAce `.json` | the design it describes ([below](#a-pyfurnace-json)) |
| `.pdb`, `.cif`, `.mmcif`, `.ent` | a structure, imported as a design ([below](#importing-an-experimental-structure)) |
| `.dat` or `.oxdna` with only the `.top` of its name beside it, or a `.top` with only its `.dat` | an oxRNA configuration, imported as a design |
| `.rtrun` | a saved run, restored without solving it again ([below](#opening-a-saved-run)) |

Any other file is refused with a message that lists the kinds of file RNAtwine reads.
A `.dat` with neither a `.txt` nor a `.top` of its name beside it is refused with that reason.

## A pyFuRNAce .json

Because RNAtwine relaxes a design's export, opening a pyFuRNAce blueprint (`.json`) opens its export when the export lies beside the `.json` or in the folder named after it and is no older than the `.json`.
Otherwise your own pyFuRNAce draws the design into the folder named after the `.json`, in a second or two, and never rewrites the `.json` you picked.
To find pyFuRNAce, the app tries these Pythons in order:

1. the path given under **Where pyFuRNAce is** in [Edit](../edit/#saving-an-edited-design)
2. the environment variable `RNATWINE_PYFURNACE_PYTHON`
3. an active conda environment
4. `python3` and `python` on the `PATH`
5. the usual conda and Homebrew locations

When none of them has pyFuRNAce, a message says so and lists each Python that the app tried, and you can open the design's `.dat` instead.

## Importing an experimental structure

A structure that has no pyFuRNAce drawing, such as a deposited PDB or mmCIF entry, a model from another program or an oxRNA configuration, is imported: its pairs and kissing loops are read from the coordinates and written as a design.
So that you can check the import before anything opens, opening such a file shows its report in the **Import structure** window.

<Figure name="open-import" />

The report lists what the import found and did, in this order:

- the `INPUT PATCHED` lines, one for each gap joined across the input's numbering, to check against the input
- the strand gaps and notes
- the **Dot-bracket** that the import inferred, which you can edit
- the **Kissing loops** that the import found, each with a box that you untick to decline the loop
- the **Locked regions**, kept at their imported geometry, each of which you can decline
- **Quality: the rebuilt model against the input**

**Re-import with these choices** runs the import again after you change any of the choices above.
**Open design** opens the design once the choices shown are the ones written.
**Write pyFuRNAce .json** writes a pyFuRNAce blueprint of the design and needs pyFuRNAce to do so.
The app writes the design, without asking where, to a folder named after the input and beside the input file.
To write it elsewhere, use the command line's `rnatwine import --out` ([Command line](../command-line/#import-a-structure)).

Because the view shows the input's coordinates and not yet the model, an imported design opens labeled `AS IMPORTED`.
A relax puts each recognized kissing loop on the model's template and the stems on A-form helices, and only the locked regions keep their imported geometry.

## Opening a saved run

A run file (`.rtrun`, written from [Export](../export/#runs-and-run-files)) opens its design under the run's settings, which become the settings of the Build step: the run's parameters, kissing-loop template, assembly or lattice, and loop roles.
The run is restored without being solved again: its energy and measures are taken at the stored coordinates, and its termination, gradient, iterations and solve time are those the file recorded.
The run joins the session's runs as a saved run.
When the session is already on the same design, the runs already in the session stay.

The status line gives the run's energy `as saved`, or `scored <E> under this version (saved <E>)` when this version of RNAtwine computes a different energy at the same coordinates.
Because the model is rebuilt from the design's files, a run file whose design is no longer where the file says is refused before anything opens, with a message that names the run file.

## What you see when a design opens

<Figure name="open-drawn" />

So that its loops can be picked and given roles before any relax, the design is drawn as pyFuRNAce drew it, built under the current settings and loop roles but not relaxed.
Until the first relax, the label under the view reads `AS DRAWN` and the drawing follows the settings in Build.
So that a burst of changes rebuilds the drawing only once, the app rebuilds it half a second after your last change to a loop role or the assembly.

Opening another design drops everything that belonged to the previous one: its results and runs, its assembly setup, its loop table and its clasp-isomer choices.

<Note title="Save runs before opening another design">
Because opening another design, unlike closing the window, drops unsaved runs without asking, first save the runs you want to keep with **Save all unsaved...** in [Export](../export/#runs-and-run-files).
</Note>
