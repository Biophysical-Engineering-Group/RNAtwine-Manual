The runs and structures of a session are kept only in memory until **Export** writes them to files.
On the rail, Export carries a badge with the number of the session's runs that are not yet saved.

## Runs and run files

<Figure name="export-runs" />

**Runs** lists every run of the session with its energy, how it ended, whether it is saved and whether it is on screen.
The session keeps only its latest 10 runs: a run that is not saved is lost when it drops out of the list, and the list then says that earlier runs were dropped.

- **View** puts a run on screen, and the structures below are then written from that run.
- **Save...** writes the run to a run file and offers the name `<design>_run<n>.rtrun`.
  <kbd>Cmd</kbd>+<kbd>S</kbd> (<kbd>Ctrl</kbd>+<kbd>S</kbd>) saves the run on screen in the same way from any step.
- **Save all unsaved (n)...** asks for a folder and writes each unsaved run there as `<design>_run<n>.rtrun`.
  A file is never replaced: a run whose file name is already taken is written beside that file under the first free number, as `<design>_run<n>_2.rtrun`, and the status line names the runs written under another name.

Because a run file does not store the map stage, a [run relaxed into a map](../inspect/#relax-into-a-map) is not written to a run file: its **Save...** is grayed, **Save all unsaved...** leaves it out, and its fitted structures, below, are its record.

Any run in the list is saved under the settings it was solved with, even when the settings in Build have changed since.
[A run file](../concepts/#runs-and-run-files) reopens with [Open...](../open/#opening-a-saved-run), serves as a block in [From runs](../build/#assemblies-of-relaxed-runs) and as a reference in [Compare](../inspect/#compare), and is read by the command-line commands `report`, `score`, `compare` and `export-pdb`.

## Structures of the run on screen

<Figure name="export-structures" />

The structures are always those of the run on screen, named in the heading (**Structures of run #n**).
When the drawing is on screen instead of a run, the panel asks you to view a run.
An earlier run is written from its own model, restored from the run's record.
The panel gives both energies when the energy at the run's coordinates differs from the energy recorded.

- **Write relaxed .dat** writes the relaxed structure as an oxDNA configuration, offered as `<name>_run<n>.relaxed.dat`, and writes the matching topology (`.top`) beside it so that the pair opens in oxView.
  For an assembly, the topology repeats the strands of every copy.
  A `.provenance.txt` beside the configuration records the parameters the structure was relaxed under.
- **Write relaxed pyFuRNAce .json** writes the relaxed shape as a pyFuRNAce blueprint that opens in pyFuRNAce.
  The button needs pyFuRNAce and is offered for an imported design or for a pyFuRNAce design with its own `.json`.
  Because a blueprint describes one design, the button is not offered for an assembly.
- **Export full-atom PDB** writes the all-atom structure of the geometry chosen in the toolbar, relaxed or drawn as the button says, and offers the name `<name>_run<n>.pdb` or `<name>_run<n>.initial.pdb`.
  Because the PDB format cannot number more than 62 strands, 9,999 residues or 99,999 atoms, the dialog also saves mmCIF (`.cif`) and proposes mmCIF for a structure too large for PDB.
  The button builds the full-atom structure first, unless the full-atom view has built it already.

As the command line's `relax --pdb` does, the full-atom PDB of a relaxed structure carries the thermal fluctuation of each nucleotide ([Colors](../inspect/#colors)) in its B-factor column, in Å, and an mmCIF file carries the fluctuation in `B_iso_or_equiv`.
A remark in the file says that the value is the harmonic fluctuation at 310 K, not a measured B-factor.
The value 999.99 marks a nucleotide whose fluctuation the model does not determine.
The file is written first, and the column is filled in once the fluctuation is computed.
Because the fluctuation belongs to the relaxed structure, a PDB of the drawn geometry carries none.

So that you can continue designing in pyFuRNAce, **Write pyFuRNAce .json** at the top of the page writes the blueprint of an imported design, with or without a relax.

## Structures of a run relaxed into a map

<Figure name="export-map-structures" />

With a [run relaxed into a map](../inspect/#relax-into-a-map) on screen, **Structures** writes the structure fitted to the map.
The line above the buttons names the frame in which the files are written.

- **Write fitted .dat** writes the oxDNA configuration, offered as `<name>_run<n>.fitted.dat`, with the matching `.top` and a `.provenance.txt` holding the map's records beside it.
- **Export fitted PDB** writes the full-atom structure, offered as `<name>_run<n>.fitted.pdb` (mmCIF for a `.cif` name), with the map's records in `REMARK 250` lines after the title.

Because a fitted structure is useful on its map, both files are written in the map's frame with the placement applied, so the PDB and the map overlap when they are opened together, without any fitting.
When the map's hand is the mirror image, no right-handed model can lie in the map as read, and a mirrored model would no longer be the model that was relaxed.
The files are then in the frame of the map's mirror image: the map reversed along x about the middle of its grid, the same map that ChimeraX's `volume flip #1 axis x` makes.

The records give the program and its version, the map's file and folder, the resolution and its source, the hand and how it was chosen, the frame, the weight and the contour.
They also give the mean distance of the sites from the contour before the relax, after it and as written, with the share of sites inside the contour, the same measures for the PDB's C1′ atoms, and the elastic energy before and after the relax.
So that you can check the fit without RNAtwine, the contour is written at the value the fit used.

To see the PDB on its map in ChimeraX, open both files:

```text
open emd_13592.map
open 5HTB_3X_run2.fitted.pdb
```

When the frame is the map's mirror image, flip the map first: ChimeraX adds the flipped map as a new model, #2, and the PDB lies in that model.

```text
open emd_13592.map
volume flip #1 axis x
open 5HTB_3X_run2.fitted.pdb
```

When the coordinates in the map's frame do not fit the columns of a PDB file, the PDB is moved until they do, and the status line says so.
Because the moved PDB no longer lies on the map, write mmCIF for such a structure.

## Image

<Figure name="export-image" />

**Export image (.png)...** writes the 3D view as it is drawn, with its colors, lighting and camera, at one, two or four times the size of the view, and each button gives its size in pixels.
The image has the background on screen, or no background with **transparent background**.
If the image cannot be drawn on the graphics path, the CPU draws it instead, with the twine as plain tubes, and the status line says so.

## Twine model

**Write twine model (.glb)** writes the structure on screen as a twine mesh, in the colors on screen, for ChimeraX, Blender and other renderers.
With **with fibers** on, each ply is a core with seven fibers wound on it.
With it off, the plies are smooth tubes and the file is about a quarter of the size.
Base pairs are rods, and every tube is a closed surface.
The coordinates are in Å, in the design's own frame, which is also the frame of an exported PDB, so the mesh lies on the atoms of that PDB.

## Quitting with unsaved runs

<Figure name="export-quit" />

When runs are unsaved, closing the window is held back once: a dialog lists the unsaved runs and offers **Go to Export**, **Quit without saving** or **Cancel**.
